BE-03 Parent accounts and verifiable consent 

Owner: Anas · Controller layer
As a parent, I want a secure account and a recorded consent for my child, so that only I control my family's data.
Build (connects FE-03)

* Register, verify email, log in, refresh, log out, forgot and reset password, and Google sign-in. Apple sign-in follows once Dina's Apple developer account is ready.
* Passwords hashed with argon2 or bcrypt. A short-lived access token, and a refresh token in an httpOnly, secure cookie.
* A verification email with a single-use link that expires after 24 hours. Until verified, the account cannot create child profiles.
* A consent record: who, when, IP address, consent text version and method. New versions add a record and never overwrite the old one.

Acceptance criteria

* A parent cannot create a child profile until their email is verified and consent is recorded.
* Verification and reset links work once, then fail with a clear message, and also fail after 24 hours.
* Wrong password, existing email, weak password and expired session return distinct error codes that FE-03 already displays.
* Repeated failed logins (default: 10 in 15 minutes) temporarily block further attempts.
* Passwords and tokens never appear in logs or API responses.
* The FE-03 screens run on the real API, with no mock left for these calls.

Email verification plus a stored consent record is the Release 1 method, pending the legal review named in the proposal.

BE-05 Roles, access rules and audit log 

Owner: Anas · Controller layer
